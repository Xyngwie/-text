# URLから短編を書く

本人が渡したURLの記事を題材に、短編を1本書きます。書き方の決まりは毎日の短編と同じで、[`stories/README.md`](../../../stories/README.md) が正です。このファイルは、題材がRSSではなく本人指定のURLになるときの差分だけを書いています。

## 手順

1. **決まりと感想を読む。** `stories/README.md` の「書き方の決まり」と `stories/feedback.md` を毎回読み直す。過去の会話の記憶より、ファイルの最新の内容を優先する。既存作品（`stories/YYYY/MM/*.md`）の形式も一つ見ておく。

2. **URLから見出しと概要を取る。**
   ```bash
   python3 tools/story_candidates.py from-url '<URL>' --output /tmp/story_url_candidate.json
   ```
   - 出力の `title`（見出し）・`description`（概要）・`publisher`（配信元）が、作品で「事実」として使ってよい範囲になる。記事本文を読めても、本文の細部は推測で補わない（README の決まり4）。
   - `already used for ...` と出たら、そのURLは既に短編になっている。本人に知らせ、別の一点で書き直すか確認する。
   - 取得に失敗した（有料記事・アクセス拒否など）、または見出しがサイト名だけで記事の中身が読めない場合は、書き始めずに本人へ見出しと概要（または本文の一部）を貼ってもらう。貼られた文を事実の範囲とし、作品の「事実と創作の区別」にその旨を書く。

3. **回避の条件に当たるか確かめる。** 事件・事故の被害者、亡くなった人、係争中の当事者、実名の個人が中心の記事なら、当人ではない架空の人物について書く（決まり5・6）。事件の端にいる人（同業者、居合わせた人、その仕事や場所に関わる別の人）から一点を拾い、当人と出来事そのものは描かない。この場合は本人への確認なしに書いてよいが、報告でどの条件に当たり、誰の視点にしたかを一行で伝える。

4. **一点を選び、主観人物を決める。** 主題でなくてよい。見出しの端の一言・数字・物の名前から拾ってよい。語彙と口調は主観人物に合わせ、本人の口癖や古風語を登場人物に言わせない。毎回同じ運び（例：まじめ＋照れ隠しの冗談）にならないようにする。

5. **作品を書く。** `stories/YYYY/MM/YYYYMMDD-HHMM-<英数字の短い名前>.md`（日本時間）。構成は既存作品と同じ。
   - 冒頭：元の記事（見出し・配信元・日付が分かれば）、URL、拾った一点、主観人物
   - `## 投稿用`：```text ブロックに題名・本文（600〜1,200字程度）・免責の一文・元記事URL。最後の2行は必ず次の形（URLは本人が渡したURLをそのまま使う）。
     ```text
     ※この物語は、下記のニュース記事から着想を得たフィクションです。登場人物や場面は創作であり、実在の人物とは関係ありません。
     元記事：<本人が渡したURL>
     ```
   - `## 事実と創作の区別`：記事から使った事実（見出し・概要から読める範囲）と、創作した部分。備考に「本人が指定したURLから書いた」と書く。

6. **登録と検査。**
   ```bash
   python3 tools/story_candidates.py register --candidates /tmp/story_url_candidate.json --candidate-id <url-...> --story <作品のパス>
   python3 tools/story_candidates.py check
   ```
   エラーが出たら作品を直してからやり直す。

7. **保存して報告。** 作品ファイルと `stories/registry.jsonl` だけをコミットし、そのセッションで決められたブランチへ push する（本人が main への直接 push を許可している場合は main）。返答では、題名・拾った一点・主観人物・作品のパスを短く伝え、投稿用ブロックの中身をそのまま載せる。続けて、スキル [`x-post-format`](../x-post-format/SKILL.md) で整えた X版も載せる。

8. **挿絵を依頼する。** スキル [`story-illustration`](../story-illustration/SKILL.md) の手順で、Google Drive の CLAUDE-GPT フォルダに `依頼_YYYY-MM-DD_<題名>.md` を置き、12時間後の受け取りを予約する（MUSE-GPT には置かない）。Drive につながっていなければ、置けなかったと報告する。

## しないこと

- Issue やコメントを作らない。
- `stories/` 以外のファイル、既存作品、`registry.jsonl` の既存行を書き換えない。
- 一つの依頼で頼まれていない本数を書かない（本人が「何本か」と言ったときだけ複数）。
- 本人が感想をくれたら、`stories/feedback.md` に「本人の感想」と「書き方への反映」を分けて追記する。型として固定するか、その回だけの感想にするかは本人の言葉に従う。
