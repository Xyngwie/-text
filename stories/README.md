# ニュースから拾う短編

ニュース記事の中にある「人の心が動く一点」を拾い、その一点だけをハイライトする短編を書く場所です。記事の主題そのものでなくてもかまいません。見出しの端にある一言、数字、物の名前など、一見関係なさそうな箇所から拾うことを歓迎します。

本人がURLを渡して頼む場合は、スキル [`short-story-from-url`](../.claude/skills/short-story-from-url/SKILL.md) の手順で書きます（題材がRSSでなく指定のURLになる以外は、この決まりと同じ）。

RSS価値観スライド（`config/rss_sources.json`、Issue作成）とは別系統です。題材は専用のニュースRSS（[`config/story_rss_sources.json`](../config/story_rss_sources.json)）から選び、Issueは作りません。

## 置き場所

- 作品：`stories/YYYY/MM/YYYYMMDD-HHMM-<短い英数字の名前>.md`
- 使った記事の登録簿：[`stories/registry.jsonl`](registry.jsonl)（追記のみ。同じ記事は二度使わない）
- 本人の感想と、そこから決めた書き方：[`stories/feedback.md`](feedback.md)

## 書き方の決まり

1. **一点に絞る。** 記事全体を要約しない。心が動く箇所を一つ選び、なぜそこを選んだかを作品の前に一、二行で書く。
2. **語彙と口調は、主観となる人物に合わせる。** 17歳の少年なら17歳の言葉、老店主なら老店主の言葉で書く。本人（神宮）の語彙・古風語・口癖を登場人物に話させない。
3. **本人らしさは、選び方・運び・止め方に出す。** 何を拾うか（主題より端の一点）、言い直して組み替える運び、美談にしすぎず言い切りすぎない締め。分析資料は [analysis/v040/voice_model.md](../analysis/v040/voice_model.md) など。ただし語彙は 2. を優先する。
4. **事実と創作を分ける。** 作品の後に「記事から使った事実」を箇条書きし、それ以外（人物名・会話・場面）は創作だと明記する。事実はRSSの見出し・概要から読める範囲だけを使い、記事本文を推測で補わない。
5. **実在の人を描かない。** 記事に出てくる個人を、そのまま実名で主人公にしたり、内心を断定したりしない。人物は架空にし、記事の出来事から少し距離を置く。
6. **傷つけない題材選び。** 事件・事故の被害者、亡くなった人、係争中の当事者を感動の材料にしない。毎日の自動の短編では、こうした条件に当たりそうな事件の記事は扱わない（専用RSSの除外語で候補から外し、すり抜けた候補も選ばない）。本人がURLを渡して頼んだ場合に限り、当人ではない架空の人物について書く（例：判決の記事なら、事件の端にいる同業者の仕事を描く）。当人と出来事そのものは描かず、善悪の判定もしない。題材として扱いにくい事件を、そうと分かる形で美談にしない。
7. **長さ。** 本文はおおむね600〜1,200字。題名を付ける。
8. **そのまま投稿できる形にする。** 作品ファイルの「## 投稿用」に ```text のブロックを置き、題名・本文・免責の一文・元記事URLをこの順で入れる。ブロックの最後の2行は必ず次の形にする（`tools/story_candidates.py check` で検査する）。

   ```text
   ※この物語は、下記のニュース記事から着想を得たフィクションです。登場人物や場面は創作であり、実在の人物とは関係ありません。
   元記事：<記事URL>
   ```

   RSSから選んだ場合、元記事URLはRSSにあるGoogle Newsのリンクで、開くと元の記事へ転送される。本人がURLを渡した場合は、そのURLをそのまま使う。

## 1本書く手順（定期実行もこの手順）

```bash
python3 tools/story_candidates.py candidates --output /tmp/story_candidates.json
```

1. 候補（最大8件）を読み、上の決まりに合い、心が動く一点がある記事を1件選ぶ。どれも合わなければ書かずに終える。
2. `stories/feedback.md` を読み、これまでの感想を反映する。
3. 作品ファイルを書く。形式は既存の作品に合わせる（冒頭に元の記事・URL・拾った一点・主観人物、次に「## 投稿用」、最後に「## 事実と創作の区別」）。
4. 登録する。
   ```bash
   python3 tools/story_candidates.py register --candidates /tmp/story_candidates.json --candidate-id <rss-...> --story stories/YYYY/MM/<file>.md
   python3 tools/story_candidates.py check
   ```
5. 作品と `stories/registry.jsonl` だけをコミットする。

## 挿絵の依頼（Google Drive の CLAUDE-GPT フォルダ）

作品を保存して push したら、スキル [`story-illustration`](../.claude/skills/story-illustration/SKILL.md) の手順で、挿絵の依頼ファイルを Google Drive の「CLAUDE-GPT」フォルダ（ID: `18AJjOCEZZTa-nw2DFd2a70T3RPIOdfc1`）に置き、置いた12時間後に完成画像の受け取りを予約する。ChatGPT が12時間おきに確認し、同じ日付・タイトルの `完成_YYYY-MM-DD_<題名>.*` を同じフォルダに置いてくれる。挿絵と投稿用テキストがそろうと投稿セットになる。フォルダ内の `運用ルール.md` が正なので、形式が変わっていないか毎回読む。

- 「MUSE-GPT」フォルダは澪の曲紹介ストーリー専用。短編の依頼は置かない。
- ファイル名：`依頼_YYYY-MM-DD_<題名>.md`（日本時間の日付。markdown のまま置き、Google ドキュメントに変換しない）
- 中身：「## 今日のショートストーリー全文（投稿用）」に、作品の「## 投稿用」ブロックの中身をそのまま（題名・本文・免責の一文・元記事URLまで）。「## 挿絵の依頼」におすすめの場面と別案、雰囲気、避けてほしいこと、用途（X投稿用）。
- 避けてほしいことには、必ず「画像内に文字を入れない」と「実在の人物・団体・ロゴを思わせる描写をしない」を入れる。事件の端を描いた回は、事件や犯罪を連想させる場面も避けてもらう。
- Google Drive につながっていないセッションでは置けない。そのときは置けなかったことを報告に書く。
- 投稿ボタンは本人が押す。Drive に置くのは制作の受け渡しだけ。
