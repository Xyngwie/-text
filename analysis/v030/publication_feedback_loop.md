# 本人修整と実投稿を戻す校正ループ

生成精度を上げる最も価値の高い材料は、AIが本人らしいと思って作った文ではなく、本人がそれを実際にどう直したかです。AI初稿だけを次の分析へ入れると、AI自身の癖を本人の口調として増幅する循環になります。

第十五版では、投稿一件を次の四層へ分けて保存します。

1. **AI初稿**：モデルが予測した文。
2. **本人修整**：本人が語彙、構文、強度、論点を直した文。
3. **本人承諾版**：公開条件と結び付いた最終文。
4. **実投稿表示**：サービス上で実際に表示された文。

## 何を学習材料にするか

中心になるのは、AI初稿と本人修整の差です。承諾は投稿権限の証拠ですが、文面を一字も直さず承諾した場合は、その案を少なくとも当該場面で許容したという弱い肯定にもなります。実投稿表示は結果確認に使いますが、リンク短縮、改行変換、文字数制限による変化を本人の癖にはしません。

| 差分 | 戻す先 | 重み |
|---|---|---|
| 誤字・表記統一 | 校正辞書 | 低 |
| 事実・固有名詞の訂正 | 事実確認工程 | 高 |
| 語彙・語尾の置換 | 口調候補 | 中 |
| 構文・段落順の変更 | 文章運び | 中〜高 |
| 立場・結論の変更 | 判断・発信モデル | 高 |
| 強度の上げ下げ | 強度2.25の校正 | 高 |
| モードの開始・終了変更 | レジスターモデル | 高 |
| プラットフォーム自動変換 | 学習しない | なし |

「重みが高い」は、一回で恒久ルールになるという意味ではありません。事実訂正は次回から同じ誤りを避けますが、価値観・語彙・構文は独立した複数投稿での反復を確認します。

## 更新の単位

投稿ごとにモデル本文を書き換えず、まず校正候補へ蓄積します。

- **単発**：その題材だけの修正かもしれないため、投稿記録に留める。
- **反復**：異なる題材で同じ修正が2件以上あれば、候補一覧へ上げる。
- **安定**：3件以上の独立投稿で同方向に直されるか、本人が一般規則として明示したら、次版の生成規則へ採用する。
- **反証**：採用済み規則と逆の修正が出たら、場面条件を探し、一律規則を弱める。

件数は機械的な真理判定ではなく、AI自身の一度の失敗を性格特性へしてしまうのを防ぐ最低限の待機条件です。

## 一件ごとの分析

一件の投稿を取り込む際は、全文の類似度だけで評価しません。

1. 本人が残した部分を確認する。
2. 本人が削った論点を確認する。
3. 本人が追加した結論・例外・比喩を確認する。
4. 強度が2.25からどちらへ動いたかを見る。
5. 通常・ギャル・お嬢様・武将の開始点と終了点が変わったかを見る。
6. 変更が本人によるものか、投稿サービスによるものか分ける。
7. 訂正理由を本人が述べた場合は、文面差分より優先して記録する。

## 次の生成へ戻す内容

次回の生成では、過去の実投稿全文をそのまま寄せ集めません。反復が確認された差分から、次のような抽象規則だけを戻します。

- 「冒頭の断定は残すが、二文目の一般論を削る」
- 「強度2.25では命令形より、見えなくなる損失を言い切る」
- 「お嬢様モードでは丁寧語より、誇張した余裕を優先する」
- 「武将調へ戻った後は説明を足さない」

元投稿の固有名詞や、その場限りの面白い言い回しを無条件に再利用しません。

## 実装

イベント履歴は `data/publication_events.jsonl`、登録・検証は `tools/publication_feedback.py` を使います。具体的なコマンドはルートの `docs/PUBLICATION_FEEDBACK.md` にまとめています。

この仕組みは投稿サービスへ接続するものではありません。投稿機能が別途実装された場合に、承諾版と送信版の一致を確認し、結果を校正データへ戻すための記録層です。
