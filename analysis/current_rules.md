# 現行の運用方針

会話・X・Issueの資料を整理し、本人の判断や話の運びを根拠付きで分析する。原典は登録時の本文を保存し、索引、分類、本人補足、分析を別に管理する。最新件数は [進捗](../PROGRESS.md) を参照する。

| 段階 | 現在の運用 |
| --- | --- |
| 1 原典と索引 | 出典・話者・本文を照合できる形で登録する |
| 2 分類 | 会話原本は文脈を精査する。Xは5分間隔で最大30件ずつAI分類案を作る。IssueのAI分析案は精読のために保存する |
| 3 判断・口調 | 本人との壁打ちと実例の精査で進める。正式版は v040。話の運び方の候補は [事例台帳](discourse_moves/README.md) で管理する |
| 4 原稿と検証 | RSSから本人確認用Issueを通常1日最大6件作る。採否・修整・実投稿報告を集めて検証する |

RSSの実行時は [生成プロンプト](../prompts/rss_value_slide.md)、v040の判断ルールと校正例を読む。強度は原稿ごとに1.50〜2.50。ポーカーの切り口は試行値25％で検討し、題材との対応が弱ければ通常の書き方に戻る。投稿本文に実験枠の注記を付けず、未確認の点はIssueに示す。短編は [専用手順](../stories/README.md) で制作する。

RSS草稿は、本人の確定本文を貼ってクローズすると採用、確定本文なしでクローズすると不採用。採用されたAI文は論旨への同意として扱い、口調は本人自身の発言や確認できる加筆・修整から読む。不採用はその草稿の採否を指す。実投稿は本人の別途報告で記録し、本人名義での公開は本人が管理する。X分類報告のクローズは整理として扱う。

運用文書の改訂前の写しは [保管庫](../archive/docs-before-2026-11-28/README.md) にある。
