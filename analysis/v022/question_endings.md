# 疑問形の四つの役割

本人の疑問形は、結論を持っていない時だけに現れるわけではありません。原本と最初の本人確定文を比べると、少なくとも四つの役割があります。生成で全部を「曖昧な問い」にまとめると、本人らしい議論の始め方まで消えてしまいます。

## 1. 情報を受け取るための質問

「APIキーって具体的にどうやって使うんでしょうか」（S081、U00723）のように、本人が答えを持たず、相手から手順や事実を受け取る質問です。この型では立場を作りません。公開投稿の締めにそのまま使うと、単なる教えてくださいになるため、発信初稿には原則使いません。

## 2. 仮説を検査する質問

「天柱も天原もダブルミーニングだからカタカナ表記にしてるのだろうか」（S016、U00114）や、「ベットは売り注文なのか？」（S422、U02579）の型です。本人は対応関係を一度置き、相手の応答で壊れるか確かめます。「だろうか」「なのか」は確信の弱さを正確に表示しています。

この型は壁打ちでは重要ですが、未確認仮説を公開断定へ変えません。RSS初稿では、事実欄ではなく着眼点や未確認事項に置きます。

## 3. 自分の言い過ぎを点検する質問

「逆じゃない？」「スキルエッジが別次元であるってことだろうか…？　流石にそこまで自画自賛するつもりはない」（S421、U02573）のように、推論を進めながら自分に都合のよい結論を抑えます。問いは逃避ではなく、結論へブレーキを掛ける装置です。

ただし、この調整を最終投稿の最後へ置くと立場がぼやけます。公開文では不確かさを本文中に限定し、最後は評価を残します。

## 4. 立場を示した後の挑戦

最初の本人確定文は、作者の意図と時間から生まれる愛着を述べたあと、「それが愛ってもんかと思うんだよ。違うか？」で閉じました。ここでは「違うか？」が結論を撤回していません。反対するなら応答せよ、という議論への招待です。

原本にも近い型があります。「知らない人からそんな感じで送られてきたURL踏まないでしょ…」（S121、U01045）は共有規範を押し出し、「斬れるときは斬るけどね？」（S532、U03233）は自分の勝負姿勢を残したまま相手の理解を促します。「搾取構造に含まれてるでしょ」「甘くなっていってない？（これがオチ）」（S555、U03359）は、評価を置いてから具体例へ落とします。

この型だけは、議論を呼ぶ公開文の末尾に使えます。条件は、疑問符を外しても直前までに本人の立場が明確であることです。

## 判定方法

末尾が疑問形なら、次の順で見ます。

1. 相手の回答がなければ主張自体が成立しないか。成立しないなら情報要求です。
2. 対応関係や因果を試しているか。そうなら仮説検査です。
3. 自分に有利な結論を弱めているか。そうなら自己点検です。
4. 疑問符を消しても本文の賛否が明確か。明確なら挑戦です。

## 生成規則

- 公開文で情報要求を結論の代わりにしない。
- 未確認の因果は「なのか」で検査してよいが、事実欄へ混ぜない。
- 自己点検は本文中に置き、末尾で主張全体を取り消さない。
- 挑戦型は、本文で一方の立場を選んだ場合だけ末尾に使える。
- 「どう思いますか？」のように読者へ判断を丸投げする定型は使わない。
- 「違うか？」「～でしょ」「～じゃない？」は毎回使わず、反対意見を実際に呼び込みたい時だけ使う。

## 現時点の扱い

本人確定文一件と、分析用プールの複数場面が同じ区別を支持しています。ただし疑問形の頻度や、公開文での使い分けはまだ実投稿で確認していません。探索的な生成規則として使い、次の校正差分を待ちます。
