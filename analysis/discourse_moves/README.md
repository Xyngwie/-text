2026-11-12の本人指定を受け、既存資料から最初の21事例を選び、5種類の切り口へ仮仕分けした。テーマ分類を置き換えるものではない。「何について話すか」とは別に、「どこへ視点を移し、どう話を進めるか」を記録する。

件数は選択した事例の主分類であり、原典全体の使用率ではない。1事例に副分類も付けるので、働きは重なり得る。5番目は特に、本人の方法選択の自己説明を多く含む。完成した発信の話法として直接観察した例と同じ強さには扱わない。

各カードには、使いどころ、話の運び、避けたい崩れ方、本人の引用、限界を記した。「避けたい崩れ方」は分析者が作った点検項目であり、本人が過去に実際に犯した失敗例という意味ではない。

## 事例と解釈を別に持つ

- [事例台帳](cases.json)：本人の引用、参照ファイル、JSON Pointer、採録時ファイルハッシュ、主分類・副分類、分析者の理由と留保。
- [候補一覧](catalog.json)：入口、展開順、使わない条件、生成への接続状態。

引用元は既存の原典採録または本チャットからの本人確認記録であり、その資料が示す出典の限界を引き継ぐ。元の会話エクスポートが未登録の本人補足を、固定原典の行番号を持つ引用として装わない。作品設定や実在人物の内心も、本人の読みと独立確認済みの事実を区別する。

例えばポーカーの3件は均質ではない。日常の奢りをポーカーで説明した作例と、ポーカーを会話や宇宙貿易に置き換えた関連例を分けた。対応を作る技法としては参考になるが、後者を「日常からポーカーへ説明した」回数へ加算しない。

## 今後の会話を読むとき

1. まず本人が何を述べたか、その前の問いや後の訂正も含めて読む。
2. 「話の運びを実際に示した例」「自分の好みや方法を説明した例」「助手の案への短い同意」を区別する。
3. どこからどこへ視点が動いたかと、その結果何が見えたかを書く。単語が出ただけで分類しない。
4. 合う候補があれば主分類と任意の副分類を付ける。合わない場合は未分類で残す。無理に5種類へ収めない。
5. 仮説や好悪と、外部の事実を分ける。後続で本人が言い直した場合は、それを保持する。

主分類は索引用の整理で、唯一の正しい読みではない。質問者が同じ型へ誘導した場合は、それを本人の自然な頻度として数えない。

## 生成に進むときの境界

現時点でRSSへ接続済みなのは、前回実装したポーカーの検討抽選25％だけ。今回の仕分けでは、その値も他の生成条件も変更していない。他4種類は分析上の候補であり、実行環境へ登録済みのスキルではない。

生成へ展開する際には、候補を確率で選ぶことと、題材へ適用できるかの判定を分ける。通常の書き方に戻る枠を残し、同じ冒頭や語尾を必須にしない。複数の働きが重なる場合も、1投稿へ全て詰め込まない。

次に不足しているのは、同じ切り口が別テーマでも自然に使えるかという照合と、本人が言わない用法の確認。今回の21事例をもって、好ましい投稿の頻度や完成した人物モデルが確定したとはしない。
