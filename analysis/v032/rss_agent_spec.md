# RSS価値観スライド実験の分析上の位置付け

RSSエージェントは、本人らしい政治意見をすでに再現できるという機能ではありません。既存の判断条件を、実績のない政治・社会題材へ移した時にどこが当たり、本人がどこを直すかを集める実験装置です。

## 二つのトラック

### 通常トラック

ゲーム、AI、技術開発など、既存ログに比較対象がある領域です。ここでは題材選択、着眼点、立場、口調をまとめて校正します。ただし、過去に同じテーマがあることは、今回の事実評価が正しいことを保証しません。

### 実験政治トラック

政治・社会は直接の実績が乏しいため、人物モデルの確定出力ではなくゼロショット予測です。政党や人物への好悪を補わず、次の既存判断だけを仮に移します。

- 取り返せない損失は何か。
- 誰が決め、失敗時に誰が直せるか。
- 利益と負担が別の人へ分かれていないか。
- 立派な名目と実際の誘因が一致しているか。
- 表示上の成果と、実質的に残る価値が同じか。

本人が修整した最終文が最初の実績になります。AI初稿を政治観の証拠にはしません。

## 「事実のみ」の限界

通信社や政府公式ソースへ絞っても、RSSの見出しと概要だけで事実の完全性・文脈・正確さを保証することはできません。感情語の除外も、客観性の証明にはなりません。

そこで入力を三段階に分けます。

1. **配信元の適格性**：直接の政府ソースか、許可した通信社名と一致するか。
2. **RSS断片の事実候補**：断片へ明記された内容だけを保持する。
3. **未確認事項**：原記事、条文、一次資料がなければ断定できない点を残す。

LLMは二段階目を短く整理できますが、三段階目を消してはなりません。Issueの候補は常に `fact_candidate_not_verified` と表示します。

## 初稿生成

判断にはv016の条件モデルを使い、通常モード・強度2.25で一つの立場を作ります。ここで強くするのは確認済み条件への評価だけです。RSS断片にない数字、因果関係、動機、違法性は足しません。

材料不足の場合は無理に投稿案を作らず、`insufficient-source` ラベルを付けます。政治枠の全Issueには、本人意見ではないことと承諾前投稿禁止を表示します。

## 本人校正を最初の実績にする

本人がIssueへ `/final` コメントを残し、本人自身が閉じた場合だけ確定文を取り込みます。

- 初稿と同じ：当該題材では無修整で許容された弱い支持。
- 語調だけ変更：口調・強度の校正。
- 着眼点を変更：価値観スライドの誤りとして高い重みで記録。
- 立場を反転：政治領域での反例として保存し、既存価値観まで直ちに否定しない。
- 投稿を見送る：題材選択または材料不足の情報として残す。確定政治意見にはしない。

独立した政治題材で修整が蓄積してから、政治領域専用の条件を作ります。最初の一件を「政治思想」として一般化しません。

## 権限分離

収集・生成側はリポジトリ内容を読んでIssueを作るだけで、履歴へ書き込みません。フィードバック側だけが履歴を書き込み、Gemini APIキーを受け取りません。

Issue本文とコメントは外部入力として扱います。本人アカウント、専用ラベル、固定マーカー、本文ハッシュ、Issueを閉じた人物を検査します。コメント文字列をシェル命令として実行しません。

## 現時点の検証段階

実装は第四段階の入口ですが、反応予測の精度検証はまだ始まっていません。RSS初稿に対する本人の修整が一件もないためです。現時点で確認できるのは、収集・区別・承諾・履歴化の機械的な流れだけです。
