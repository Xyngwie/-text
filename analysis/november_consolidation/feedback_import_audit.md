# 評価コメントと確定文の混同を防ぐ

2026-11-04、Issue #221・#234・#238の本人コメントは初稿への評価であると精査済みだったが、過去の取り込み処理では投稿本文と承認へ変換されていた。確認できた影響イベントは [監査記録](feedback_import_audit.json) に、入力台帳のハッシュとともに記録した。

## 修正

`data/issue_reviews.jsonl` の `feedback_kind: draft_verdict` を参照する共通処理を追加した。Issue番号、コメントID、本文SHA-256のすべてが一致する版だけに適用する。原典や過去のイベント履歴は書き換えない。

- 今後の取り込みでは、該当コメントを確定文・承認として登録しない。
- 誤取り込み済みの評価文へ、後から「投稿しました」を結びつけない。コマンド側の承認利用でも同様に止める。
- 校正用の投稿ペアを新しく作る際にも該当する評価文を除外する。
- 本人が別に確定文を提示した場合や、同じコメントの本文が編集された場合は、その新しい内容を通常どおり扱う。

既存の `/final` による明示的な確定文指定は保持する。自然な投稿文に「言わない」が含まれるという理由だけでは除外しない。

## 検証と残る範囲

3つの実データを用いて、評価の除外、本文改訂の別扱い、明示的確定文、過去の誤承認の利用停止、正しい確定文の後続投稿、校正ペアからの除外を回帰テストした。既存の投稿イベント・校正・RSSのテストも通過。

今回の対応は精査結果を取り込みへ反映する仕組みであり、任意の自由文の意味を完全自動判定するものではない。定型判定語以外の新しい評価コメントは、引き続き原典と文脈で確認する必要がある。原典は保存されるため、後から同じ方式で分類を追加できる。

過去イベントをそのまま件数集計する処理には、当時の誤った承認も残る。そうした集計を有効な承認数・本人の投稿数として使わず、手動レビューとこの監査を併読する。凍結済みの過去分析や生成に使う校正スナップショットは変更していない。
