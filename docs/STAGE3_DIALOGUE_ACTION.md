# 第三段階をIssueで壁打ちする

本人の2026年10月23日の指示により、第三段階の問いの作成と、本人の返答を受けた暫定分析を自動化します。本人の返答なしに人物像を確定する処理ではありません。

## 本人がすること

`stage3-dialogue` ラベルのIssueを読み、普通にコメントしてください。賛成、訂正、具体例、分からない、今は違う、といった短い返答で構いません。Closeや特別なタグは不要です。閉じたIssueのコメントも読みます。「次へ」とだけコメントすると、そのテーマを保留して次へ進みます。Closeだけでは同意・完了・次テーマへの指示と扱いません。

一度に未回答のテーマを一件だけ出します。毎時の起動時に返答がなければ、Geminiを呼ばず待ちます。本人コメントの作成・編集も起動の合図です。AIの発言は一テーマ最大3回（初回＋補足2回）でいったん区切り、次の定時実行で別テーマへ進みます。最後の回で未解決の点は未解決として残し、本人承認済みにはしません。AIが早めに区切る場合もあります。

## 根拠の選び方

第一・第二段階済みのCopilot本人発言とX投稿を対象にし、本人文と分類されたものを同じ話題から最大6件選びます。可能なら会話とXを比較します。一発言40〜3000文字、少なくとも異なる分類区間・返信単位の2件が必要です。文字数や分類の条件により、全原本を網羅するものではありません。

XのAI分類を本人確認済みとは呼びません。原本のハッシュ、分類と本文、原文の部分引用を検証し、根拠ID・URLはコード側で固定します。分類区間の違いも独立した案件の証明ではないため、内容上の重複・同じ出来事の再送は分析時に留保します。返信先や前後がないものは、その不足を残します。

問いは短い観察・暫定仮説・限界・質問一つで構成し、人物像の美化や口癖の機械的挿入を求めません。本人の返答も引用・貼り付けを含み得る資料であり、その全体を独自の信条や実投稿とはしません。過去の同テーマの返答と直近3テーマの暫定整理を次の対話の参考に渡します。

## 保存と反映の境界

- `analysis/dialogues/D*/turn-*.json`：根拠原文、本人の返答、AIの仮説・訂正・質問、モデル、日時、基準コミット、指示と入力のハッシュ。生成してコミットした後にIssueへ送ります。
- `data/stage3_dialogue_receipts.json`：配信結果。保存済みの出力は未配信なら次回再送し、Issueとコメントのマーカーで重複送信を防ぎます。
- `sources/github-issues-001/snapshots.jsonl`：本人コメントとIssueの文脈。既存の原典保管も併用します。

正式な `analysis/vNNN`、既存の仮説件数、分類台帳、RSS生成指示は自動変更しません。第三段階の対話資料が増えることと、第四段階の生成への反映は別です。第三段階は引き続き本人との対話で進め、その窓口をこのチャットに加えてIssueにも設ける変更です。

区切り済みのテーマへの後日の補足・編集も原典には残りますが、自動応答は再開しません。必要なら後の壁打ちで再検討します。返答が長すぎる場合や検証に失敗した場合は、勝手に省略して先へ進まずActionを停止します。

## 設定と停止

ワークフロー：`.github/workflows/stage3_dialogue.yml`。毎時11分（UTC）の起動設定ですが、GitHub側の遅延・欠落があります。手動実行もできます。実行ごとに最大1回の生成・配信です。第二段階の最大30件は変更しません。

既存の `GEMINI_API_KEY` と標準 `GITHUB_TOKEN` を使います。Variable `STAGE3_DIALOGUE_MODEL` は省略時 `auto`、安定版Flash優先で最大3モデルまで不適合時に試します。`STAGE3_DIALOGUE_PAUSED=true` でこの壁打ちだけを止められます。第三段階の自動問い出しを止めても、第二段階の分類や原典保管は継続します。

Issue作成・コメントは今回の本人指示によって行います。本人名義のSNS投稿は一切行いません。Issuesの通知はGitHub側の購読・通知設定によります。
