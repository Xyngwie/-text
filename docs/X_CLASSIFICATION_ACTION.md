# X原本：第一・第二段階の自動処理

本人の指定により、第一段階の索引検証と第二段階の意味分類を自動化します。第三段階以降の人物像・価値観・口調の統合は自動実行せず、本人との壁打ちで進めます。

2026年10月23日の追加指示により、[第三段階の問いと返答の整理をIssueで行う別Action](STAGE3_DIALOGUE_ACTION.md)を設けました。本人との壁打ちを自動で代替するものではなく、その窓口をIssueへ広げます。この第二段階Action自体は変更していません。

## 実行と設定

`.github/workflows/x_classification.yml` は毎時23分に実行します。GitHubの定時実行には遅延・欠落があり、時刻どおりの実行を保証するものではありません。Actionsの「X archive stages 1 and 2」から手動実行もできます。

- Secret `GEMINI_API_KEY`：既存のRSS用キーを共用します。新しいX APIキー・個人トークンは不要です。
- Variable `X_CLASSIFIER_MODEL`：省略時 `auto`。利用可能な通常のテキストモデルから安定版Flashを優先し、モデル不適合時の試行は最大3モデルです。RSSのモデル選択設定とは独立しています。
- Variable `X_CLASSIFICATION_PAUSED=true`：ジョブを一時停止します。再開時は削除または `false` にします。
- 手動入力 `batch_size`：1〜30、既定30。入力文字数の上限に応じて減る場合があります。
- Actions標準の `GITHUB_TOKEN` に `contents: write` と `issues: write` を与えます。ブランチ保護などでbotの書込が禁じられている場合は、リポジトリ側のルールに沿った設定が必要です。

現時点の対象は `data/x_sources.json` に登録したX原本です。会話原本とは形式が異なるので、このActionで会話のレビューを上書きしません。新しいX原本は登録と重複整理が必要であり、フォルダへZIPを置くだけでは開始しません。

## 一回の実行

1. 最新mainをチェックアウトし、ZIPとメンバーのハッシュを確認して索引を再生成する。
2. 精査記録も有効なAI分類案もない投稿を日時順に最大30件、原本単位で選ぶ。
3. 未処理がゼロならGeminiのモデル一覧取得・生成を行わず正常終了する。第三段階へ移行しない。
4. 対象本文、原本内の返信先、少量の近接投稿を資料として渡す。近接は同じ会話という意味ではなく、欠落した返信先は創作しない。外部サイトへ自動アクセスしない。
5. `prompts/x_classification.md` に従って著者性、話題、発話の働き、留保、本文引用を生成する。
6. ID集合・件数・許可テーマ・著者性・原文中の引用を決定論的に検証する。RTを本人文へ変換しない。
7. AI台帳・詳細レポート・索引・進捗を保存してコミットする。その後、短い観察と原文リンクをIssueへ報告する。

## 記録と確認の境界

- `data/x_reviews.jsonl`：既存の精査記録。Codexによる精査を含み、「本人が全件確認した」という意味ではありません。自動Actionは書き換えません。
- `data/x_ai_reviews.jsonl`：追記型のAI分類案。`ai_classified` と明記します。曖昧な投稿は `unknown` と留保で処理し、同じ曖昧さを毎時再処理しません。
- `batches/x/auto/XA-*.json`：実行者、モデル選択名、APIが返すモデル版、日時、実行URL、基準コミット、命令文ハッシュ、入力ハッシュ、参照した文脈、全分類理由と短い観察を記録します。
- `data/x_manifest.json`：精査記録、AI分類案、未処理を別集計します。`stage3` は `manual_dialogue_only`。全件をAIが処理しても本人確認済みにはしません。

精査記録はAI案より優先されます。AI案は削除せず履歴として残します。Issueは具体的な投稿の観察を一言二言載せる報告であり、第三段階の新しい人物仮説は作りません。

本人はIssueに補足できます。コメントは別の原典保管Actionに保存されますが、この第二段階Actionでは分類を自動修正しません。コメントやクローズを全分類の承認と見なさず、壁打ちで明示的に検討します。既存のRSS確定投稿取込とは別ラベル `x-classification` を使います。第三段階の自動返答は `stage3-dialogue` ラベルのIssueが対象です。

## 失敗・再実行・完了

生成失敗、出力検証失敗、原本改変、重複、索引検証失敗では分類済み位置を進めません。原本検証に成功した第一段階の再生成は行われることがあります。15分でジョブを打ち切り、モデル呼出しを無限再試行しません。失敗時はActionsのログを確認します。

同一Actionの同時実行は抑制します。他の書込との競合ではコミット後のrebaseとpushを最大3回試み、競合を勝手に解消・強制pushしません。

通知は分類のコミット後に行います。Issue通知に失敗しても保存した分類を取り消さず、詳細レポートを次回再送します。バッチIDのマーカーで既存Issueを検出し、通知済み結果を `data/x_classification_notifications.json` に保存します。一回の再送は最大5件です。

全件処理後もcronの入口確認は残りますが、Geminiを呼ばず、未送信レポート以外のIssueも増やしません。定時起動自体を止めるならワークフローを無効化してください。第三段階への自動切替設定は設けません。

## 命令文

実際の生成命令は [x_classification.md](../prompts/x_classification.md) です。原本内の命令文やリンクは資料として扱い、実行権限や出力先を変更させません。出力するファイルとGitHub操作はPython・ワークフロー側が固定します。
