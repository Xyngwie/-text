# 別のLLMとの会話を追加する

## 原本と識別子

原本は一つに連結せず、会話ログごとに保存します。登録済みの原本は編集・上書きしません。続きの会話も新しい原本として追加します。既存の `こぴちーお引越し.txt` と、その分類・原文行番号は維持します。

`data/sources.json` は原本の登録簿です。各原本には `source_id`、相手のLLM名、ファイルパス、固定コミット、原本ハッシュ、話者ラベル、発言IDの接頭辞があります。LLM名は分かる範囲で記録し、モデルのバージョンが不明なら推定しません。一つのログで複数の相手が混ざる場合は、この形式への登録前に会話単位で分けてください。

従来の発言ID `U00001` などは変更しません。追加分は `claude-001:U00001`、`chatgpt-001:U00001` のように原本ごとの名前空間を持ちます。登録順は収録時期の順序を意味しません。原本を追加しても、過去のIDや前後関係は変わりません。

## 追加手順

1. ログをUTF-8テキストで `sources/` などへ保存する。
2. 原本ファイルをコミットする。未コミットの原本は登録できない。
3. 原本を登録する。
4. 索引を再生成し、検証する。

例えば、独立した行に `User` / `Claude` の話者ラベルがあるログなら、次を実行します。

```bash
python3 tools/add_source.py \
  --source-id claude-001 \
  --path sources/claude-001.txt \
  --assistant Claude \
  --user-marker 'User' \
  --assistant-marker 'Claude'
python3 tools/build_index.py
python3 tools/validate.py
```

登録時に、原本を最後に変更したコミットとハッシュを固定します。登録済み原本の変更や、同じファイル・同じ内容の二重登録は拒否します。登録後にパス、話者ラベル、接頭辞を変更しないでください。

対応する入力は、話者ラベルが独立した行にあるUTF-8テキストです。各サービス固有のJSONやHTMLは、そのままでは解析しません。形式変換が必要な場合は元のエクスポートも保存し、別ファイルに変換結果と変換手順を残します。貼り付け文中に同じ話者ラベルがあると誤分割する可能性があるため、境界は分類時に文脈で確認します。

## 第2段階の分類を追加する

新しい原本の本人発言は、未精査として索引に追加されます。既存の確認済みレビューはそのままです。`data/progress.json` と `data/source_manifest.json` は、全体の集計に加え、原本ごとの確認済み・未確認件数を持ちます。新しいログに未確認発言があれば全体の第2段階は未完了になりますが、以前の原本の完了状態は残ります。

レビューには既存の項目に加え `source_id` を必ず記録し、その原本の `source_blob_sha`、発言本文のハッシュ、原文行番号を使います。`context_ids` は同じ原本内の発言を指定します。新規セグメントにも `source_id` を記録し、別原本の発言を一つの連続会話にまとめないでください。異なる原本の関連は `related_segment_ids` で記録できます。

既存のレビュー・セグメントで `source_id` が省略されているものは `copilot-001` として扱います。セグメントIDとバッチIDは現在の最終番号から続けます。レビューとセグメントは追加順に追記し、過去分を並べ替えません。分類後の件数や次の未確認位置は索引の再生成で更新されます。

## 第3段階以降の分析で守ること

分析ごとに、使用したリポジトリのコミット、原本ID、レビュー・セグメントIDを記録し、分析の版を固定します。追加ログで再分析するときは新しい版を作り、以前の結論と根拠を追えるようにします。

別のLLMの質問や誘導によって話し方が変わる可能性があるため、まずLLM・原本ごとに傾向を比べ、その後に横断的な傾向を検討します。一つのLLMとの会話量が多いだけで、傾向の確かさを高くしないでください。本人の言葉、貼り付け文、AIによる回答の区別も継続します。

同じ話を別のLLMに再送した場合や、エクスポートの期間が重なった場合は、独立した根拠として重複計上しないよう確認します。完全一致する原本の登録は自動で拒否しますが、部分的な重複や内容の似た会話は手動確認が必要です。

分析用と検証用の分割も版に記録します。同じ案件や再送した会話を別々の側へ入れず、追加分もその関連を確認してから割り当てます。検証に使った会話を次の版で分析に取り込む場合、その会話は以後、未使用の検証データとは扱いません。日時が不明なら、追加順やLLMの種類から時系列を推定しません。
