# Copilot会話ログのテーマ分類

## 目的

長期の壁打ちログをテーマ別に参照できる形に整理し、後の段階で「神宮がニュースのどこに注目し、どう判断し、どんな口調で感想を述べるか」を、根拠付きで分析する。ログから得られる傾向は本人の完全な人格モデルではなく、会話内で観察されたものとして扱う。

## 原本と今回の作業

現在のリポジトリにある原本は `こぴちーお引越し.txt`。`.md` は現在のmainにはない。原本は改名・編集せず、分類はこのディレクトリに追加した。年を特定できない表示や「今日」などから、収録期間や時系列を補完しない。

今回作ったものは、話者ラベルによる発言区間の抽出、原文の行番号・ハッシュを持つ索引、本人発言のキーワードから作ったテーマ候補。全発言の文脈を読んだ意味分類は未完了。

- [テーマ別索引](INDEX.md)：人間が読む入口。
- [作業ガイドライン](GUIDELINES.md)：自動化エージェントおよび作業者向けの公式作業基準書・分類マニュアル。
- [オートメーション指示文](AUTOMATION_INSTRUCTIONS.md)：Cursor Automations（クラウドエージェント）向け設定プロンプト。
- `data/utterances.jsonl`：本人とCopilotを区別した発言索引。
- `data/source_manifest.json`：原本の固定コミット、ハッシュ、件数、解析上の注意。
- `data/taxonomy.json`：仮のテーマ定義とキーワード。
- `data/reviews.jsonl`：人が文脈を確認した分類。自動生成では上書きしない。
- `data/segments.jsonl`：トピック別のセグメント定義。
- `tools/build_index.py`：索引を再生成する処理。
- `tools/validate.py`：レビュー・セグメント・進捗データの整合性自動検証スクリプト。

原本へのリンクは固定コミットに向ける。索引のプレビューは検索用の冒頭抜粋であり、発言の要約ではない。発言IDは現在の原本内の出現順で、原本の追加・並べ替え後の永続識別子ではない。原本を更新したときはハッシュとレビューを照合し、過去のレビューを自動で別の発言へ移さない。

## 分類方針

1. ひとつの発言をひとつのテーマに固定しない。横断的な会話には複数テーマを付ける。
2. 短い相槌や「それ」などは、前後の本人発言とCopilot回答を読んで分類する。キーワードのない発言を自動で前のテーマへ押し込まない。
3. Copilotの文章量や「神宮らしい」などの人物評を、本人の傾向の根拠にしない。
4. 本人発言欄に貼られた第三者の文章、AI生成文、メモリ一覧、ニュース記事は、本人自身の意見と区別する。
5. 質問・仮説・冗談・感想・否定・明確な同意を分ける。質問しただけで、その立場を支持しているとは扱わない。
6. ニュースの話題か、日常の話題か、一般論か、判定不能かを別に記録する。キーワード一致だけでニュース扱いにしない。
7. 日付不明・話者境界不明・意図不明はそのまま残す。

## 作業順序

### 第1段階：参照可能な索引（今回）

原本を保存し、全ての検出発言にID・話者・原文位置を付ける。仮のテーマ一覧を作る。検出ラベルが引用の一部ではないか、原本の形式も確認する。

### 第2段階：文脈を読んだ分類

原文順に、本人発言を20〜40件程度ずつ確認する。前後の応答を含めて話題の区間を決める。テーマ候補を修正し、ニュースとの関係、発言の種類、貼り付け文の有無を記録する。候補のない発言も必ず確認する。

区間は元の出現順を保つ。離れた場所に再登場した同じ話題には関連リンクを付け、ひとつの架空の連続会話に合成しない。複数の話題が同時に進む場合は重複区間を許可する。

### 第3段階：テーマ横断の分析

複数の確認済み区間から、着眼点、判断の条件、感情のきっかけ、反例・変化、本人の口調を抽出する。一度の発言を恒常的な価値観にしない。Copilotが与えた言葉を本人が採用したかも確認する。

### 第4段階：ニュース反応の再現と検証

分類・分析に使っていない本人発言を検証用に残す。モデルにはニュースと必要な文脈だけを渡し、隠した本人の感想と比較する。着眼点、判断、感情、口調を別々に評価し、本人にも違和感を確認してもらう。ニュース自体の事実確認と、過去ログに基づく反応の推定は分ける。

## レビューの記録形式

`data/reviews.jsonl` の1行が1件の確認結果。自動候補を直接確定扱いに変えるのではなく、このファイルに判定を追加する。

- `utterance_id`, `source_blob_sha`, `body_sha256`：原文との対応。
- `theme_labels`：確認したテーマ。
- `news_relation`：`news` / `general` / `personal` / `unknown`。
- `speech_act`：質問、提案、感想、訂正、同意、仮説など。
- `authorship`：`own` / `pasted` / `mixed` / `unknown`。
- `evidence_lines`：判断根拠となる原文行範囲。
- `context_ids`：一緒に確認した発言。
- `note`：判定の理由、不明点。

確認済みの分類は人格分析の確定を意味しない。初期のレビュー例は分類方法を示すための小さな見本。

## 再生成

リポジトリのルートで実行する。

```bash
python3 classification/tools/build_index.py
```

Python標準ライブラリとGitだけを使用。原本と手動レビューは書き換えない。発言区間の連続性、IDの重複、Copilotの発言を本人のテーマ候補にしないことを処理内で検査する。
